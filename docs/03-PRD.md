## 1. 产品概述

### 1.1 产品定位

IPMS（Integrated Project Management System）是一个面向企业内部业务系统的**需求开发全生命周期管理平台**。系统统一管理 SAP B1、Salesforce、Weaver OA（外部采购）以及 VPMS、Logistics Portal、Tools、CAD（内部自研）共 7 个业务系统的需求、任务、缺陷和文档，支撑甲方（内部 IT 团队）、乙方（供应商团队）、最终用户（系统用户）三方高效协作。

### 1.2 核心价值

| 维度 | 核心价值 |
|------|---------|
| 统一入口 | 一个平台管理所有业务系统的需求，告别信息分散 |
| 流程标准化 | 7 状态需求流转机制，确保需求从提出到验收可追溯 |
| 三方协作 | 甲方-供应商-用户三层权限隔离，各司其职 |
| 跨系统关联 | 支持需求同时关联多个业务系统，各侧独立跟踪进度 |
| 变更可追溯 | 需求变更版本记录，谁在什么时间改了什么一目了然 |
| 质量管控 | 内置缺陷管理与验收流程，保障交付质量 |

### 1.3 产品范围

#### MVP 范围内（P0）

- 项目管理：手动创建/编辑/查看业务系统项目
- 需求与变更管理：7 状态流转、跨系统关联、子任务拆分、版本记录
- 任务与进度跟踪：分配、认领、到期提醒
- 缺陷与质量管理：提交、分级、修复跟踪、验收
- 文档管理：项目级文档存储、接口文档（结构化模板 + 富文本）、变更版本记录
- 权限与组织架构：三类用户独立组织树、行级数据隔离、三级内部角色
- 通知：Outlook 邮件集成、到期提醒
- 操作日志：完整操作记录、前端可查

#### MVP 范围外

- 甘特图（P1）
- 数据报表 / 看板（P2）
- 移动端（P2）
- 工时填报（P2）
- 知识库功能（待评估）

### 1.4 产品目标

| 目标类型 | 目标描述 | 衡量指标 |
|---------|---------|---------|
| 业务目标 | 支撑 7 个业务系统的需求全生命周期管理 | 所有系统需求均通过 IPMS 流转 |
| 效率目标 | 需求交付过程可视化、可追溯 | 需求状态流转平均耗时可度量 |
| 协作目标 | 三方用户各司其职，数据安全隔离 | 零越权访问事件 |
| 质量目标 | 缺陷可追踪至修复闭环 | 缺陷修复率可度量 |
| 交付目标 | MVP 1-3 个月内交付上线 | 核心功能可用的系统上线运行 |

## 2. 用户角色与权限矩阵

### 2.1 三类用户总览

| 用户类型 | 定义 | 组织架构 | 典型角色 |
|---------|------|---------|---------|
| 内部 IT 团队 | 企业信息化部门员工 | 独立维护 | 超级管理员、项目经理、项目成员 |
| 供应商团队 | 外部软件开发商 | 独立维护 | 项目经理、开发人员、测试人员 |
| 系统用户 | 各业务部门员工 | 独立维护 | 需求提出人（普通用户） |

### 2.2 内部 IT 团队角色定义

| 角色 | 职责描述 | 典型场景 |
|------|---------|---------|
| 超级管理员 | 全局管理，拥有系统最高权限 | 创建系统项目、管理用户账号、分配项目归属、查看全量操作日志 |
| 项目经理 | 管理所负责项目的需求全生命周期 | 审核需求、分配任务给供应商/内部成员、跟踪进度、验收上线 |
| 项目成员 | 参与具体需求的执行和协作 | 编辑需求、拆分任务、更新任务状态、提交缺陷 |

### 2.3 供应商团队角色定义

| 角色 | 职责描述 | 典型场景 |
|------|---------|---------|
| 项目经理 | 管理供应商侧的需求交付 | 接收甲方分配的需求、分配内部开发任务、汇报进度 |
| 开发人员 | 承接开发任务并执行 | 认领任务、更新开发进度、修复缺陷 |
| 测试人员 | 供应商内部测试 | 提交测试结果、验证缺陷修复 |

> 说明：供应商项目管理员由内部 IT 超级管理员预先创建，供应商人员无需自行注册。供应商内部角色可在其团队组织架构内继续细分。

### 2.4 系统用户角色定义

| 角色 | 职责描述 | 典型场景 |
|------|---------|---------|
| 需求提出人 | 提交业务需求给 IT 团队 | 填写需求表单、查看需求进度、参与最终验收 |

> 说明：系统用户内部角色分级留待第二期细化。MVP 阶段系统用户均视为"需求提出人"。

#### 数据权限规则

| 用户类型/角色 | 可见数据范围 |
|-------------|------------|
| 内部 IT — 超级管理员 | 全局所有数据：所有项目、需求、任务、缺陷、文档、操作日志 |
| 内部 IT — 项目经理 | 按分配范围：被分配管理的项目及其下所有需求、任务、缺陷、文档 |
| 内部 IT — 项目成员 | 按分配范围：被分配参与的项目及其相关数据 |
| 供应商团队 | 仅可见被分配的项目、需求、任务、缺陷。不可见其他供应商的数据 |
| 系统用户 | 仅可见自己提交的需求及其状态。不可见其他人的需求 |

### 2.6 组织架构说明

三类用户各自维护独立的组织架构树：

- **内部 IT 团队**：按部门-团队-人员构建树形结构，支持三级角色（超管/项目经理/项目成员）在树中标记
- **供应商团队**：按供应商公司-团队-人员构建树形结构，一个平台可接入多个供应商
- **系统用户**：按部门-岗位-人员构建树形结构，反映业务部门的组织结构

组织架构树的功能：
- 支持查看、新增、编辑、删除节点
- 人员可归属到树节点下
- 项目可关联到特定组织节点（如指定某项目由某供应商负责）

## 3. 功能规格

### 模块一：项目（系统）管理

#### 3.1.1 功能描述

以业务系统（如 SAP B1、Salesforce 等）为管理单元，由内部 IT 管理员手动创建和维护项目基本信息。项目是需求、任务、缺陷、文档的管理容器。

#### 3.1.2 用户场景

| 场景编号 | 场景描述 | 操作角色 |
|---------|---------|---------|
| S1-01 | 信息化部门新增了一个业务系统（如新采购的 ERP），需要在 IPMS 中创建对应的管理项目 | 内部 IT 超级管理员 |
| S1-02 | 管理员需要更新项目的基本信息（如更换供应商、修改负责人） | 内部 IT 超级管理员 |
| S1-03 | 某个项目不再需要管理，管理员尝试删除，但系统提示已有关联需求，禁止删除 | 内部 IT 超级管理员 |
| S1-04 | 供应商项目经理登录系统，查看自己被分配管理的项目列表 | 供应商项目经理 |
| S1-05 | 项目经理查看所负责项目的需求总览 | 内部 IT 项目经理 |

#### 3.1.3 项目信息字段

| 字段 | 说明 | 是否必填 |
|------|------|:------:|
| 项目名称 | 如"SAP B1"、"Salesforce" | 是 |
| 系统类型 | 外部采购 / 内部自研 | 是 |
| 项目描述 | 项目的简要说明 | 否 |
| 状态 | 活跃 / 维护中 / 归档 | 是 |
| 负责人 | 内部 IT 项目经理（从组织架构选择） | 是 |
| 供应商 | 负责该系统的供应商（从供应商组织架构选择） | 否（内部自研可不填） |
| 创建时间 | 系统自动生成 | 自动 |
| 更新时间 | 系统自动维护 | 自动 |

#### 3.1.4 操作流程

**创建项目：**
1. 内部 IT 超级管理员进入项目管理页面
2. 点击"新建项目"
3. 填写项目信息表单（名称、类型、描述、负责人等）
4. 如有外部供应商，指定供应商团队
5. 提交保存，系统生成项目记录
6. 项目创建后，项目经理和供应商可在各自范围内查看

**编辑项目：**
1. 管理员进入项目详情页，点击"编辑"
2. 修改项目信息字段
3. 保存更新，系统记录修改时间

**删除项目：**
1. 管理员在项目列表中选择目标项目，点击"删除"
2. 系统检查该项目是否已关联需求
3. 如已关联需求，提示"该项目已关联 N 条需求，无法删除。如需移除，请先将关联的需求移动至其他项目或删除。"
4. 如未关联需求，弹出二次确认："确认删除项目 [项目名称]？此操作不可撤销。"
5. 确认后删除项目

#### 3.1.5 业务规则

| 编号 | 规则描述 |
|------|---------|
| BR-1-01 | 仅内部 IT 超级管理员可创建和编辑项目 |
| BR-1-02 | 项目名称不可重复 |
| BR-1-03 | 已关联需求的项目禁止删除（数据完整性保护） |
| BR-1-04 | 项目归档后，不可新增需求，但可查看历史数据 |
| BR-1-05 | 维护中状态的项目，已有功能正常使用，新需求需审批后创建 |

#### 3.1.6 输入/输出

| 项 | 描述 |
|----|------|
| 输入 | 项目基本信息表单（名称、类型、描述、状态、负责人、供应商） |
| 输出 | 项目列表、项目详情、删除确认提示 |

### 模块二：需求与变更管理

#### 3.2.1 功能描述

需求管理是 IPMS 的核心模块。涵盖需求从提出到验收的全生命周期管理，支持需求录入、审核、分配、状态流转、跨系统关联、子任务拆分，以及需求变更的版本记录。

#### 3.2.2 需求信息字段

| 字段 | 说明 | 是否必填 |
|------|------|:------:|
| 需求标题 | 需求的简要标题 | 是 |
| 需求描述 | 需求的详细描述 | 是 |
| 所属项目 | 关联的业务系统（可多选） | 是 |
| 优先级 | 紧急 / 高 / 中 / 低 | 是 |
| 需求类型 | 新功能 / 功能优化 / 缺陷修复 / 系统对接 / 其他 | 是 |
| 提出人 | 系统用户（自动关联当前用户） | 自动 |
| 提出时间 | 系统自动记录 | 自动 |
| 期望完成时间 | 期望的上线时间 | 否 |
| 当前状态 | 7 状态之一 | 自动 |
| 审核人 | 负责审核的项目经理 | 状态推进时赋值 |
| 开发负责人 | 供应商开发负责人 | 分配时赋值 |
| 当前版本号 | 需求变更次数（v1, v2...） | 自动 |
| 附件 | 需求相关文档、截图等 | 否 |

#### 3.2.3 七状态流转定义

| 状态 | 含义 | 可执行操作 | 操作者 |
|------|------|-----------|--------|
| 待审核 | 需求刚提交，等待甲方审核 | 通过（→已分配）/ 驳回 | 内部 IT 项目经理 |
| 已分配 | 审核通过，已分配至供应商 | 开始开发（→开发中）/ 退回审核 | 供应商项目经理 |
| 开发中 | 供应商正在开发 | 完成开发（→测试中）/ 挂起 | 供应商开发人员 |
| 测试中 | 供应商内部测试或甲方测试 | 测试通过（→待上线）/ 打回开发（→开发中） | 供应商测试 / IT 项目成员 |
| 待上线 | 测试通过，等待发布上线 | 确认上线（→已上线） | 内部 IT 项目经理 |
| 已上线 | 已发布到生产环境 | 发起验收（→已验收）/ 回退 | 内部 IT 项目经理 |
| 已验收 | 需求提出人确认验收 | 归档（终态） | 系统用户（需求提出人） |

#### 3.2.4 用户场景

| 场景编号 | 场景描述 | 操作角色 |
|---------|---------|---------|
| S2-01 | 业务部门员工登录系统，提交新的业务需求，关联到 SAP B1 系统 | 系统用户 |
| S2-02 | IT 项目经理审核待审核列表，通过某需求并分配给供应商 | 内部 IT 项目经理 |
| S2-03 | IT 项目经理审核时发现需求不清晰，驳回并附审核意见 | 内部 IT 项目经理 |
| S2-04 | 供应商项目经理将需求分配给内部开发人员 | 供应商项目经理 |
| S2-05 | 供应商开发完成，提交测试，状态从开发中→测试中 | 供应商开发人员 |
| S2-06 | 测试通过，状态推进至待上线，IT 项目经理安排上线 | 内部 IT 项目经理 |
| S2-07 | 需求上线后，提出人登录确认，状态从已上线→已验收 | 系统用户 |
| S2-08 | 需求涉及 VPMS 和 SAP B1 对接，同时在两个系统视图中可见 | 多方 |
| S2-09 | 需求执行过程中内容发生变更，系统记录版本变更历史 | 内部 IT 项目成员 |

#### 3.2.5 跨系统关联规则

- 创建需求时，"所属项目"支持多选，一个需求可同时关联多个业务系统
- 需求在关联的每个系统视图下均可见
- 各系统侧独立管理自己的任务和进度
- 需求的状态在所有关联系统中保持一致（需求级状态统一）
- 需求详情页展示所有关联系统及其各自的子任务完成情况

#### 3.2.6 子任务拆分规则

- 需求下可拆分为多个子任务
- 甲方（内部 IT）和乙方（供应商）均可拆分任务
- 每个子任务独立分配、独立跟踪、独立到期提醒
- 子任务有独立的状态：待开始 / 进行中 / 已完成 / 已挂起
- 需求整体进度基于子任务完成比例计算

#### 3.2.7 需求变更与版本记录

- 需求的核心信息（标题、描述、优先级、关联系统等）发生修改时，视为一次变更
- 每次变更自动递增版本号（v1 → v2 → v3...）
- 版本记录包含：变更时间、变更人、变更字段、变更前值、变更后值
- 需求详情页展示版本历史列表，可查看每次变更的详细 diff
- 状态流转不算变更（状态变更有独立的流转日志）

#### 3.2.8 操作流程

**提交需求：**
1. 系统用户登录，进入"我的需求"页面
2. 点击"提交新需求"
3. 填写需求标题、描述、选择关联系统（可多选）、优先级、需求类型
4. 可选：上传附件、设置期望完成时间
5. 提交，需求状态初始为"待审核"
6. 系统自动通知相关项目经理有待审核需求

**审核需求：**
1. 内部 IT 项目经理查看待审核需求列表
2. 打开需求详情审阅
3. 选择操作：
   - 通过：填写审核意见，指定供应商 → 状态变为"已分配"
   - 驳回：填写驳回原因 → 需求回到提出人处修改

**需求变更记录：**
1. 有权限的用户编辑需求核心字段
2. 提交修改时，系统自动比对变更内容
3. 生成变更记录（变更人、时间、字段、新旧值）
4. 版本号自动递增

#### 3.2.9 业务规则

| 编号 | 规则描述 |
|------|---------|
| BR-2-01 | 需求提出人仅可查看和编辑自己提交的需求 |
| BR-2-02 | 状态流转必须遵循定义路径，不可跳状态 |
| BR-2-03 | 驳回的需求回到提出人处，修改后重新提交进入"待审核" |
| BR-2-04 | 需求关联系统至少选择一个 |
| BR-2-05 | 已验收需求不可再编辑或修改状态（归档保护） |
| BR-2-06 | 子任务全部完成后，需求方可进入测试中 |
| BR-2-07 | 版本记录自动生成，不可手动修改或删除 |

### 模块四：缺陷与质量管理

#### 4.4.1 功能描述

对已上线或测试中的需求进行缺陷管理闭环。支持缺陷提交、分级、指派修复、复测、验收确认，保障交付软件质量。

#### 4.4.2 缺陷信息字段

| 字段 | 说明 | 是否必填 |
|------|------|:------:|
| 缺陷标题 | 简要描述缺陷现象 | 是 |
| 缺陷描述 | 复现步骤、期望结果、实际结果 | 是 |
| 关联需求 | 缺陷关联的需求 | 是 |
| 关联项目 | 从需求继承 | 自动 |
| 严重程度 | 致命 / 严重 / 一般 / 轻微 | 是 |
| 缺陷类型 | 功能缺陷 / 性能缺陷 / UI缺陷 / 兼容性 / 其他 | 是 |
| 发现人 | 提交缺陷的人 | 自动 |
| 发现时间 | 系统自动 | 自动 |
| 发现阶段 | 测试中 / 已上线后 | 是 |
| 指派人 | 负责修复的人 | 指派后填写 |
| 当前状态 | 待确认 / 已确认 / 修复中 / 待复测 / 已关闭 / 重新打开 | 自动 |
| 复现截图 | 附件 | 否 |
| 修复说明 | 开发人员填写的修复方案 | 修复时填写 |

#### 4.4.3 缺陷严重程度定义

| 级别 | 名称 | 定义 | 处理时效建议 |
|:----:|------|------|:----------:|
| P0 | 致命 | 系统崩溃、数据丢失、安全漏洞 | 4 小时内响应 |
| P1 | 严重 | 核心功能不可用、无替代方案 | 24 小时内响应 |
| P2 | 一般 | 非核心功能异常、有替代方案 | 3 个工作日内 |
| P3 | 轻微 | UI 瑕疵、文案错误、体验问题 | 下一迭代 |

#### 4.4.4 缺陷状态流转

```
待确认 → 已确认 → 修复中 → 待复测 → 已关闭
                    ↑         ↓
                    └─ 重新打开 ←┘
```

- **待确认**：缺陷提交后初始状态，等待甲方确认是否确认为缺陷
- **已确认**：甲方确认是有效缺陷，指派给供应商修复
- **修复中**：供应商正在修复
- **待复测**：供应商提交修复，等待甲方重新测试
- **已关闭**：复测通过，缺陷关闭
- **重新打开**：复测不通过，重新指派修复

#### 4.4.5 用户场景

| 场景编号 | 场景描述 | 操作角色 |
|---------|---------|---------|
| S4-01 | 测试人员在测试中发现接口返回值格式错误，提交缺陷并附截图 | 内部 IT 项目成员 / 供应商测试 |
| S4-02 | IT 项目经理审核确认缺陷，指派给供应商开发人员修复 | 内部 IT 项目经理 |
| S4-03 | 供应商开发人员修复后填写修复说明，状态推进至待复测 | 供应商开发人员 |
| S4-04 | 测试人员复测通过，关闭缺陷 | 内部 IT 项目成员 |
| S4-05 | 业务部门用户上线后发现页面显示问题，提交缺陷 | 系统用户 |

#### 4.4.6 操作流程

**提交缺陷：**
1. 用户进入缺陷管理页面，点击"提交缺陷"
2. 选择关联需求（或从需求详情页直接提交）
3. 填写缺陷标题、描述、严重程度、类型、复现步骤
4. 可上传截图附件
5. 提交，状态初始为"待确认"

**修复缺陷：**
1. IT 项目经理确认缺陷（待确认→已确认），指派修复人
2. 供应商开发人员收到指派，开始修复（已确认→修复中）
3. 修复完成，填写修复说明，提交复测（修复中→待复测）
4. 测试人员复测：
   - 通过：关闭缺陷（待复测→已关闭）
   - 不通过：重新打开（待复测→重新打开→修复中）

#### 4.4.7 业务规则

| 编号 | 规则描述 |
|------|---------|
| BR-4-01 | 缺陷必须关联一条已有需求 |
| BR-4-02 | 缺陷发现阶段为"测试中"时，关联需求必须处于"测试中"状态 |
| BR-4-03 | 已关闭的缺陷可重新打开（如再次发现同样问题） |
| BR-4-04 | 致命和严重缺陷在所有关联缺陷列表中高亮标记 |
| BR-4-05 | 缺陷关闭前，关联需求不可推进至下一状态 |

#### 4.4.8 输入/输出

| 项 | 描述 |
|----|------|
| 输入 | 缺陷表单（标题、描述、严重程度、类型、关联需求、截图附件） |
| 输出 | 缺陷列表（按状态/严重程度筛选）、缺陷详情、修复记录 |

#### 5.5.3 接口文档结构化模板

### 模块六：权限与组织架构

#### 6.6.1 功能描述

管理三类用户各自独立的组织架构树，实现人员归属管理和项目分配。基于角色和项目归属实现功能权限控制和行级数据隔离。

#### 6.6.2 组织架构管理

**内部 IT 团队组织树：**
- 树根：信息化部门
- 下级节点：按团队/小组划分（如开发组、运维组、SAP 组等）
- 叶子节点：团队人员
- 每个人员在树中标记角色（超管 / 项目经理 / 项目成员）

**供应商团队组织树：**
- 树根：供应商公司名称
- 下级节点：按团队/项目组划分
- 叶子节点：供应商人员
- 每个人员在树中标记角色（项目经理 / 开发人员 / 测试人员）

**系统用户组织树：**
- 树根：公司
- 下级节点：按部门划分（财务部、销售部、采购部等）
- 叶子节点：部门员工

#### 6.6.3 权限控制机制

**功能权限：**
- 基于用户角色定义可执行的操作（见 2.5 权限矩阵）
- 菜单和操作按钮根据权限动态显示/隐藏

**数据权限（行级隔离）：**
- 内部 IT 超管：全局数据
- 内部 IT 项目经理/成员：基于项目分配范围
- 供应商用户：基于被分配的项目和需求
- 系统用户：仅自己的需求

**内容级权限：**
- 同一页面内，不同角色看到不同的操作按钮
- 例如：需求详情页，项目经理可见"审核"按钮，供应商可见"开始开发"按钮

#### 6.6.4 供应商账号管理

- 供应商账号由内部 IT 超级管理员预先创建
- 创建时指定所属供应商公司/团队、角色
- 系统生成初始密码，首次登录需修改
- 供应商可自行管理内部人员的角色分配（在自身组织树范围内）
- 供应商人员离职或项目结束，管理员可禁用账号（而非删除）

#### 6.6.5 用户场景

| 场景编号 | 场景描述 | 操作角色 |
|---------|---------|---------|
| S6-01 | 管理员在组织架构中新增一名 IT 项目经理，分配管理 SAP B1 和 Salesforce 项目 | 内部 IT 超级管理员 |
| S6-02 | 供应商 A 的项目经理在其组织树中新增一名开发人员 | 供应商项目经理 |
| S6-03 | 管理员将一个项目从供应商 A 移交给供应商 B，原供应商失去访问权限 | 内部 IT 超级管理员 |
| S6-04 | 系统用户登录后，仅看到自己提交的需求列表，无法查看其他人的需求 | 系统用户（系统自动） |

#### 6.6.6 业务规则

| 编号 | 规则描述 |
|------|---------|
| BR-6-01 | 三类用户的组织架构树完全独立，互不可见 |
| BR-6-02 | 供应商仅可见自身公司的组织树，不可见其他供应商 |
| BR-6-03 | 账号禁用后不可登录，但历史操作记录保留 |
| BR-6-04 | 项目切换供应商时，历史数据归属不变，新供应商仅可见交接后的新需求 |
| BR-6-05 | 超级管理员权限不可被其他角色修改或删除 |

#### 6.6.7 输入/输出

| 项 | 描述 |
|----|------|
| 输入 | 组织树节点创建/编辑表单、人员添加表单、角色分配、项目供应商分配 |
| 输出 | 组织架构树视图、人员列表、权限生效后的功能菜单和数据范围 |

#### 7.7.1 功能描述

通过集成 Outlook 邮箱系统，实现任务/需求到期提醒等邮件通知。MVP 阶段聚焦于到期望通知，后续迭代扩展更多通知场景。

#### 7.7.2 通知类型

### 模块八：操作日志

#### 8.8.1 功能描述

记录系统中所有关键操作，形成完整的审计追踪链条。日志支持前端查询展示，便于问题排查和责任追溯。

#### 8.8.2 日志记录内容

| 字段 | 说明 |
|------|------|
| 日志编号 | 唯一标识 |
| 操作时间 | 精确到秒的操作时间戳 |
| 操作人 | 执行操作的用户（姓名 + 账号） |
| 用户类型 | 内部 IT / 供应商 / 系统用户 |
| 操作模块 | 项目管理 / 需求管理 / 任务管理 / 缺陷管理 / 文档管理 / 权限管理 |
| 操作类型 | 创建 / 编辑 / 删除 / 状态变更 / 审核 / 分配 / 上传 / 下载 |
| 操作对象 | 被操作的对象（项目名称 / 需求标题 / 任务标题等） |
| 操作详情 | 变更前后的内容对比（关键字段），状态变更记录旧状态→新状态 |
| IP 地址 | 操作来源 IP |

#### 8.8.3 需记录的操作

| 操作类型 | 示例 |
|---------|------|
| 项目创建/编辑 | "创建了项目 SAP B1" |

| 需求状态变更 | "需求 VPMS对接 状态：待审核→已分配" |

| 用户管理 | "创建了供应商账号：李四 (供应商A)" |

#### 8.8.4 日志查询功能

| 查询条件 | 说明 |
|---------|------|
| 时间范围 | 起止日期选择 |
| 操作人 | 按用户名搜索 |

```
                          [驳回修改后重新提交]
                               ↑
                               │
  [系统用户提交需求]  →  [1. 待审核]  →  [审核通过]  →  [2. 已分配]
                                                           │
                                                           ↓
                                              [供应商项目经理分配开发]
                                                           │
                                                           ↓
                                                    [3. 开发中]
                                                       │        │
                                           [打回开发]  │        │  [开发完成]
                                                       ↓        ↓
                                              [4. 测试中] ←──┘
                                                   │
                                        [测试通过]  │
                                                   ↓
                                              [5. 待上线]
                                                   │

                                                   ↓
```

**状态流转权限映射：**

| 状态转换 | 操作者 |
|---------|--------|
| → 待审核 | 系统用户（提交需求） |
| 待审核 → 已分配 | 内部 IT 项目经理（审核通过） |
| 待审核 → 待审核 | 内部 IT 项目经理（驳回，提出人修改后重新提交） |
| 已分配 → 开发中 | 供应商项目经理 |
| 开发中 → 测试中 | 供应商开发人员 / 内部 IT 项目成员 |
| 测试中 → 开发中 | 供应商测试人员 / 内部 IT 项目成员（测试不通过） |
| 测试中 → 待上线 | 内部 IT 项目经理（测试通过） |
| 待上线 → 已上线 | 内部 IT 项目经理（上线确认） |
| 已上线 → 已验收 | 系统用户（验收确认） |

```
  ┌─────────────┐
  │  系统用户    │
  │  提交需求    │
  │  关联系统：  │
  │  VPMS + SAP  │

  └──────┬───────────────┬──────────────────────┘
         │               │
         ▼               ▼
  ┌──────────────┐ ┌──────────────┐
```

- 附件上传/删除（记录在操作日志模块）

## 7. 验收标准

### 7.1 模块验收标准

#### 7.1.1 模块一：项目（系统）管理

| 编号 | 验收项 | 验收标准 |
|:----:|--------|---------|
| AC-1-1 | 创建项目 | 管理员可成功创建新项目，填写所有必填字段后保存成功，项目出现在项目列表中 |
| AC-1-2 | 编辑项目 | 管理员可编辑项目信息，保存后信息更新，更新时间字段自动刷新 |
| AC-1-3 | 删除空项目 | 未关联需求的项目可成功删除，删除前有二次确认弹窗 |
| AC-1-4 | 删除有需求的项目 | 已关联需求的项目删除时，系统提示"该项目已关联 N 条需求，无法删除"，阻止删除操作 |
| AC-1-5 | 权限验证 | 非管理员用户无法看到创建/编辑/删除项目的操作入口 |
| AC-1-6 | 项目归档 | 归档项目后不可新增需求，历史数据可正常查看 |
| AC-1-7 | 数据隔离 | 供应商仅可见自己被分配的项目，不可见其他供应商的项目 |

#### 7.1.2 模块二：需求与变更管理

| 编号 | 验收项 | 验收标准 |
|:----:|--------|---------|
| AC-2-1 | 提交需求 | 系统用户可提交需求，支持多选关联系统，提交后状态为"待审核" |
| AC-2-2 | 审核通过 | IT 项目经理审核需求并分配供应商，状态变为"已分配" |
| AC-2-3 | 审核驳回 | IT 项目经理驳回需求并附原因，需求回到提出人处可修改重提 |
| AC-2-4 | 7 状态完整流转 | 需求可按照定义路径依次流转至"已验收"，每步流转操作者符合权限矩阵 |
| AC-2-5 | 越权流转阻止 | 非授权角色无法执行状态推进操作（如系统用户不能将状态推至开发中） |
| AC-2-6 | 跨系统关联 | 关联多系统的需求在各系统视图下均可见，系统名称正确展示 |
| AC-2-7 | 子任务拆分 | 甲方和供应商均可在需求下创建子任务，子任务独立分配和跟踪 |
| AC-2-8 | 版本变更记录 | 修改需求核心字段后，版本号自动递增，变更记录包含变更人、时间、字段、新旧值 |
| AC-2-9 | 版本历史查看 | 需求详情页可查看完整版本变更列表，每次变更的差异清晰可辨 |
| AC-2-10 | 已验收保护 | 已验收需求不可编辑和修改状态 |
| AC-2-11 | 数据隔离 | 系统用户仅见自己提交的需求；供应商仅见被分配的需求 |

#### 7.1.3 模块三：任务与进度跟踪

| 编号 | 验收项 | 验收标准 |
|:----:|--------|---------|
| AC-3-1 | 创建任务 | 有权限用户可在需求下创建任务，填写标题、截止日期、负责人等信息 |
| AC-3-2 | 任务认领 | 负责人可认领任务，状态从"待开始"变为"进行中" |
| AC-3-3 | 任务完成 | 负责人可将任务标记为完成，状态变为"已完成" |
| AC-3-4 | 任务挂起 | 负责人可挂起任务并填写原因，挂起任务不计入进度计算 |
| AC-3-5 | 进度可视化 | 需求详情页展示任务完成百分比进度条 |
| AC-3-6 | 到期提醒 | 任务到期前 N 天系统自动发送 Outlook 邮件提醒负责人 |
| AC-3-7 | 逾期提醒 | 逾期任务每天早上发送提醒邮件，直至任务完成 |
| AC-3-8 | 提醒配置 | 可配置全局提醒时间和个人提醒开关 |

#### 7.1.4 模块四：缺陷与质量管理

| 编号 | 验收项 | 验收标准 |
|:----:|--------|---------|
| AC-4-1 | 提交缺陷 | 用户可提交缺陷，关联需求、选择严重程度和缺陷类型 |
| AC-4-2 | 缺陷分级 | 支持致命/严重/一般/轻微四级，致命和严重在列表中高亮标记 |
| AC-4-3 | 缺陷确认 | IT 项目经理可确认缺陷（待确认→已确认）并指派修复人 |
| AC-4-4 | 缺陷修复 | 修复人可填写修复说明并提交复测（修复中→待复测） |
| AC-4-5 | 复测通过 | 测试人员复测通过后缺陷关闭（待复测→已关闭） |
| AC-4-6 | 复测不通过 | 测试人员可重新打开缺陷（待复测→重新打开→修复中） |
| AC-4-7 | 缺陷关联约束 | 关联需求未完成的缺陷阻止需求推进至下一状态 |

#### 7.1.5 模块五：文档管理

| AC-5-9 | 文档回收站 | 删除的文档进入回收站，30 天后自动清理 |
