## 1. 设计概述

### 1.1 数据库选型理由

| 考量维度 | 说明 |
|---------|------|
| 数据完整性 | PostgreSQL 15 原生支持 Row-Level Security (RLS)，可作为应用层权限隔离的最后一道防线 |
| JSON 支持 | 操作日志变更详情、接口文档结构化参数均可使用 JSONB 字段，支持索引和高效查询 |
| 复杂查询 | 跨模块关联查询（需求关联多项目、任务按供应商过滤）在 PostgreSQL 查询优化器下表现更优 |
| Laravel 兼容性 | Laravel Eloquent ORM 对 PostgreSQL 支持完善（JSONB 查询、递归 CTE、完整事务支持） |
| 递归查询 | CTE（WITH RECURSIVE）天然适合组织架构树的递归遍历，与 Laravel Query Builder 的 `withRecursiveExpression` 直接集成 |
| 许可证 | PostgreSQL License 完全免费，无合规风险 |
| 规模匹配 | <50 并发、<20 项目、万级记录，PostgreSQL 资源消耗在单机部署下完全可控 |

### 1.2 命名规范

| 对象 | 规范 | 示例 |
|------|------|------|
| 表名 | `snake_case` 复数形式（Laravel Eloquent 默认） | `requirements`、`projects`、`audit_logs` |
| 主键 | `id`，自增整数（Laravel 默认） | `id BIGSERIAL PRIMARY KEY` |
| 外键 | `{related_model}_id` | `project_id`、`submitter_id` |
| 普通字段 | 小写+下划线（snake_case） | `created_at`、`is_active` |
| 布尔字段 | `is_` 前缀 | `is_active` |
| 时间字段 | `_at` 后缀 | `created_at`、`updated_at`、`deleted_at` |
| 唯一索引 | `ux_{table}_{field}` | `ux_projects_name` |
| 普通索引 | `ix_{table}_{field}` | `ix_requirements_status` |
| 联合索引 | `ix_{table}_{field1}_{field2}` | `ix_audit_logs_module_action` |
| 多对多中间表 | 关联的两表名按字母序排列，单数形式 | `permission_role`、`organization_user`、`role_user` |

### 1.3 字符集与排序规则

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 数据库编码 | UTF-8 (UTF8) | 支持中文及多语言 |
| 排序规则 | zh_CN.UTF-8 | 中文排序规则 |
| 字符类型 | varchar (变长) / text (无限制) | 避免使用 char (定长) 浪费空间 |
| 时区 | Asia/Shanghai (UTC+8) | 所有时间戳统一使用带时区的时间类型 |

### 1.4 Laravel Eloquent 模型约定

| 约定 | 说明 |
|------|------|
| 主键 | 所有表使用 Laravel 默认的 `id`（自增整数），Eloquent 自动管理 |
| 模型基类 | 所有 Eloquent Model 继承自框架 `Illuminate\Database\Eloquent\Model` |
| 时间戳 | `created_at`、`updated_at` 由 Eloquent 自动维护（`$timestamps` 属性） |
| 软删除 | 需要回收站/逻辑删除的表使用 Laravel 内置 `SoftDeletes` trait（提供 `deleted_at` 字段，自动过滤已删除记录） |
| 外键 | 使用 Eloquent Relationship（`belongsTo`、`hasMany`、`belongsToMany`），外键由数据库 Migration 中的 `foreign()` / `references()` / `on()` / `onDelete()` 定义 |
| 枚举 | 使用 PHP 8.1+ Backed Enum 或在 Model 中定义常量，数据库存储整数或短字符 |
| Mass Assignment | 使用 `$fillable` 或 `$guarded` 属性控制批量赋值安全 |
| Query Scope | 通过 Eloquent Query Scope（`scopeVisibleToUser` 等）封装行级数据过滤和常见查询条件 |

### 3.3 组织架构模型

#### 3.3.1 `organizations` -- 组织架构树表

使用 `parent_id + 递归 CTE (WITH RECURSIVE)` 实现树形结构，三类用户各自拥有独立的根节点，通过 `org_type` 字段区分。

与原先 Django MPTT 方案（`lft`/`rght`/`tree_id`/`level` 字段）相比，此方案的优势：
- 插入、移动节点无需重新计算左右值，写操作开销更低
- 无需引入额外的 tree 库，直接使用 PostgreSQL 递归 CTE 进行树查询
- 更直观的 parent_id 引用，易于理解和维护
- 小规模数据（<500 节点）下递归 CTE 性能完全满足需求

| 字段名 | 数据类型 | 长度/精度 | 必填 | 默认值 | 说明 |
|--------|---------|:--------:|:----:|--------|------|
| `id` | SERIAL | -- | 是 | 自增 | 主键 |
| `parent_id` | INTEGER | -- | 否 | NULL | 父节点 FK -> self（NULL 表示根节点） |
| `name` | VARCHAR | 100 | 是 | -- | 节点名称（如"开发组"） |
| `org_type` | SMALLINT | -- | 是 | -- | 组织类型：1=内部IT, 2=供应商, 3=系统用户 |
| `description` | TEXT | -- | 否 | NULL | 节点描述 |
| `is_active` | BOOLEAN | -- | 是 | TRUE | 是否启用 |
| `created_at` | TIMESTAMPTZ | -- | 是 | now() | 创建时间 |
| `updated_at` | TIMESTAMPTZ | -- | 是 | now() | 更新时间 |

**索引：**
- `ix_organizations_parent`: 普通索引 (`parent_id`)
- `ix_organizations_org_type`: 普通索引 (`org_type`)

**树查询方式：**

获取某节点及其所有子节点（递归 CTE）：
```sql
WITH RECURSIVE org_tree AS (
    -- 锚点：起始节点
    SELECT id, parent_id, name, org_type, 0 AS depth
    FROM organizations
    WHERE id = :start_id
    
    UNION ALL
    
    -- 递归：所有子节点
    SELECT o.id, o.parent_id, o.name, o.org_type, ot.depth + 1
    FROM organizations o
    JOIN org_tree ot ON o.parent_id = ot.id
)
SELECT * FROM org_tree ORDER BY depth, id;
```

获取某节点的祖先链：
```sql
WITH RECURSIVE org_ancestors AS (
    SELECT id, parent_id, name, org_type, 0 AS depth
    FROM organizations
    WHERE id = :start_id
    
    UNION ALL
    
    SELECT o.id, o.parent_id, o.name, o.org_type, oa.depth + 1
    FROM organizations o
    JOIN org_ancestors oa ON o.id = oa.parent_id
)
SELECT * FROM org_ancestors ORDER BY depth DESC;
```

获取完整子树（用于行级数据隔离的供应商范围查询）：
```sql
WITH RECURSIVE org_subtree AS (
    SELECT id FROM organizations WHERE id = :supplier_root_id
    UNION ALL
    SELECT o.id FROM organizations o JOIN org_subtree os ON o.parent_id = os.id
)
SELECT p.id, p.name FROM projects p
WHERE p.supplier_org_id IN (SELECT id FROM org_subtree);
```

**递归 CTE 查询封装（Laravel Query Builder）：**
```php
// 获取某节点所有子孙节点
$descendants = DB::table('organizations')
    ->withRecursiveExpression('org_tree', function ($query) use ($nodeId) {
        // 锚点
        $query->select('id', 'parent_id', 'name', 'org_type', DB::raw('0 as depth'))
            ->from('organizations')
            ->where('id', $nodeId)
            // 递归
            ->unionAll(
                DB::table('organizations as o')
                    ->join('org_tree as ot', 'o.parent_id', '=', 'ot.id')
                    ->select('o.id', 'o.parent_id', 'o.name', 'o.org_type', DB::raw('ot.depth + 1'))
            );
    })
    ->from('org_tree')
    ->orderBy('depth')
    ->get();

// 获取某节点所有祖先
$ancestors = DB::table('organizations')
    ->withRecursiveExpression('org_ancestors', function ($query) use ($nodeId) {
        $query->select('id', 'parent_id', 'name', 'org_type', DB::raw('0 as depth'))
            ->from('organizations')
            ->where('id', $nodeId)
            ->unionAll(
                DB::table('organizations as o')
                    ->join('org_ancestors as oa', 'o.id', '=', 'oa.parent_id')
                    ->select('o.id', 'o.parent_id', 'o.name', 'o.org_type', DB::raw('oa.depth + 1'))
            );
    })
    ->from('org_ancestors')
    ->orderByDesc('depth')
    ->get();
```

## 6. 关键查询场景与索引策略

### 6.1 场景一：按项目查询需求列表（按状态筛选、分页）

**业务背景：** 用户进入项目详情页，查看该项目下的所有需求，支持按状态筛选和分页。

**SQL 示例：**
```sql
SELECT r.id, r.title, r.priority, r.status, r.submitter_id, r.created_at,
       u.display_name AS submitter_name
FROM requirements r
JOIN requirement_project rp ON r.id = rp.requirement_id
JOIN users u ON r.submitter_id = u.id
WHERE rp.project_id = 6
  AND r.status = ANY(ARRAY[1, 2, 3])  -- 筛选待审核、已分配、开发中
ORDER BY r.created_at DESC
LIMIT 20 OFFSET 0;
```

**Laravel Eloquent 等价写法：**
```php
$requirements = Requirement::query()
    ->whereHas('projects', fn ($q) => $q->where('projects.id', 6))
    ->whereIn('status', [1, 2, 3])
    ->with('submitter:id,display_name')
    ->orderByDesc('created_at')
    ->paginate(20);
```

**执行计划分析：**
```
Index Scan using ix_requirement_project_project on requirement_project rp
  -> Nested Loop Join on requirements r
     -> Index Scan using requirements_pkey on r
        Filter: status = ANY(...)
```

**所需索引：**
| 索引 | 作用 |
|------|------|
| `ix_requirement_project_project` (project_id) | 通过项目快速定位关联的需求 ID |
| `requirements_pkey` (id) | 通过需求 ID 获取需求详情 |
| `ix_requirements_status_priority` (status, priority) | 对状态筛选后的数据进一步按优先级排序 |

**预估性能：** 单项目通常关联 <100 条需求，即使加上状态筛选，数据集仍在百级。查询耗时 <50ms。

### 6.2 场景二：按用户查询其可见的需求（行级数据隔离查询）

**业务背景：** 供应商用户登录后查看"我的需求"列表，只能看到被分配到的项目中的需求。

**SQL 示例（供应商用户 id=15，所属供应商 org_id=3）：**
```sql
-- Step 1: 获取该供应商公司及其所有子节点
WITH RECURSIVE supplier_orgs AS (
    SELECT id FROM organizations WHERE id = 3
    UNION ALL
    SELECT o.id FROM organizations o
    JOIN supplier_orgs so ON o.parent_id = so.id
)

-- Step 2: 查询可见需求
SELECT DISTINCT r.id, r.title, r.status, r.priority, r.created_at
FROM requirements r
JOIN requirement_project rp ON r.id = rp.requirement_id
JOIN projects p ON rp.project_id = p.id
WHERE p.supplier_org_id IN (SELECT id FROM supplier_orgs)
ORDER BY r.created_at DESC
LIMIT 20 OFFSET 0;
```

**Laravel 等价实现（Eloquent Query Scope）：**
```php
// Requirement.php Model
class Requirement extends Model
{
    public function scopeVisibleToUser(Builder $query, User $user): Builder
    {
        if ($user->isSuperAdmin()) {
            return $query;
        }

        return match ($user->user_type) {
            UserType::INTERNAL => $query->whereHas('projects.members', fn ($q) =>
                $q->where('user_id', $user->id)
            ),
            UserType::SUPPLIER => $this->applySupplierScope($query, $user),
            UserType::SYSTEM_USER => $query->where('submitter_id', $user->id),
            default => $query->whereRaw('1 = 0'), // 未知类型不返回任何数据
        };
    }

    private function applySupplierScope(Builder $query, User $user): Builder
    {
        $supplierOrg = $user->organizations()
            ->where('org_type', OrgType::SUPPLIER)
            ->first();

        if (! $supplierOrg) {
            return $query->whereRaw('1 = 0');
        }

        // 使用递归 CTE 获取供应商公司下所有子节点
        $descendantIds = DB::table('organizations')
            ->withRecursiveExpression('org_tree', function ($q) use ($supplierOrg) {
                $q->select('id')->from('organizations')
                    ->where('id', $supplierOrg->id)
                    ->unionAll(
                        DB::table('organizations as o')
                            ->join('org_tree as ot', 'o.parent_id', '=', 'ot.id')
                            ->select('o.id')
                    );
            })
            ->from('org_tree')
            ->pluck('id');

        return $query->whereHas('projects', fn ($q) =>
            $q->whereIn('supplier_org_id', $descendantIds)
        );
    }
}
```

**Laravel Policy 方式（用于控制器授权）：**
```php
// RequirementPolicy.php
class RequirementPolicy
{
    public function view(User $user, Requirement $requirement): bool
    {
        if ($user->isSuperAdmin()) return true;

        return match ($user->user_type) {
            UserType::INTERNAL => $requirement->projects()
                ->whereHas('members', fn ($q) => $q->where('user_id', $user->id))
                ->exists(),
            UserType::SUPPLIER => $this->canSupplierView($user, $requirement),
            UserType::SYSTEM_USER => $requirement->submitter_id === $user->id,
            default => false,
        };
    }
}
```

**所需索引：**
| 索引 | 作用 |
|------|------|
| `ix_requirement_project_requirement` (requirement_id) | 从需求反向查关联的项目 |
| `ix_requirement_project_project` (project_id) | 从项目查关联的需求 |
| `ix_projects_supplier_org` (supplier_org_id) | 按供应商过滤项目 |
| `ix_organizations_parent` (parent_id) | 递归 CTE 子节点 JOIN |
| `ix_organizations_org_type` (org_type) | 按组织类型过滤 |
| `ix_requirements_submitter` (submitter_id) | 系统用户查自己的需求 |
| `ix_project_members_user` (user_id) | 内部 IT 用户查被分配的项目 |

**预估性能：** 涉及 3 表 JOIN + 1 个递归 CTE。对于万级需求、百级项目，通过索引可控制在 <100ms。

### 6.3 场景三：到期任务扫描（定时任务查询）

**业务背景：** Laravel Scheduler 每天早上 9:00 触发扫描，找出所有需要发送到期提醒的任务。

**SQL 示例：**
```sql
-- 查询所有需要提醒的任务：
-- 1. 未完成的任务 (status IN (1,2)) 且截止日期已到或已逾期
-- 2. 或者截止日期在未来 N 天内（N = remind_days_before）
-- 3. 且上次提醒不在同一提醒窗口内（避免重复发送）

SELECT t.id, t.title, t.due_date, t.remind_days_before,
       t.assignee_id, t.requirement_id, t.project_id,
       u.email AS assignee_email,
       u.display_name AS assignee_name,
       r.title AS requirement_title,
       p.name AS project_name,
       pm.user_id AS it_pm_user_id  -- 抄送的 IT 项目经理
FROM tasks t
JOIN users u ON t.assignee_id = u.id
JOIN requirements r ON t.requirement_id = r.id
JOIN projects p ON t.project_id = p.id
LEFT JOIN project_members pm ON p.id = pm.project_id AND pm.role_in_project = 'pm'
WHERE t.status IN (1, 2)  -- 待开始、进行中（不包含已完成和已挂起）
  AND t.due_date <= (CURRENT_DATE + t.remind_days_before)  -- 到达提醒窗口
  AND (
      t.last_reminded_at IS NULL
      OR t.last_reminded_at < (CURRENT_DATE - t.remind_days_before)  -- 不在同一窗口
  )
  AND t.assignee_id IS NOT NULL
ORDER BY t.due_date;
```

**Laravel Artisan Command 示例：**
```php
// app/Console/Commands/ScanDueReminders.php
class ScanDueReminders extends Command
{
    protected $signature = 'reminders:scan-due';

    public function handle(): void
    {
        $tasks = Task::query()
            ->whereIn('status', [1, 2])
            ->whereRaw('due_date <= CURRENT_DATE + remind_days_before')
            ->where(function ($q) {
                $q->whereNull('last_reminded_at')
                  ->orWhereRaw("last_reminded_at < CURRENT_DATE - remind_days_before");
            })
            ->whereNotNull('assignee_id')
            ->with(['assignee:id,email,display_name', 'requirement:id,title', 'project:id,name'])
            ->orderBy('due_date')
            ->get();

        foreach ($tasks as $task) {
            SendDueReminder::dispatch($task);
        }
    }
}
```

**所需索引：**
| 索引 | 作用 |
|------|------|
| `ix_tasks_due_remind` (status, due_date) | 核心索引：按未完成状态 + 到期时间范围扫描 |
| `ix_tasks_assignee` (assignee_id) | JOIN 用户表获取邮箱 |
| `ix_tasks_requirement` (requirement_id) | JOIN 需求表获取标题 |
| `ix_tasks_project` (project_id) | JOIN 项目表获取名称 |
| `ix_project_members_project` (project_id) | 查找项目对应的 IT PM |

**预估性能：** 定时任务每天运行一次，扫描全量未完成任务（预估 <500 条）。通过 `ix_tasks_due_remind` 索引，扫描范围进一步缩小到到期窗口内的任务。总耗时 <200ms。

### 6.4 场景四：操作日志多条件组合查询

**业务背景：** 用户在操作日志页面按时间范围、操作模块、操作类型、操作人组合查询。

**SQL 示例：**
```sql
SELECT id, user_display_name, user_type, module, action_type,
       target_name, detail, ip_address, created_at
FROM audit_logs
WHERE created_at BETWEEN '2026-07-01' AND '2026-08-03'
  AND module = 2          -- 需求管理
  AND action_type = 4     -- 状态变更
  AND user_id = 25        -- 可选：按用户筛选
ORDER BY created_at DESC
LIMIT 50 OFFSET 0;
```

**Laravel Eloquent 等价写法：**
```php
AuditLog::query()
    ->whereBetween('created_at', ['2026-07-01', '2026-08-03'])
    ->where('module', 2)
    ->where('action_type', 4)
    ->when($request->user_id, fn ($q, $id) => $q->where('user_id', $id))
    ->orderByDesc('created_at')
    ->paginate(50);
```

**所需索引：**
| 索引 | 作用 |
|------|------|
| `ix_audit_logs_created_at` (created_at DESC) | 时间范围主索引 |
| `ix_audit_logs_module_action` (module, action_type) | 模块+类型联合筛选 |
| `ix_audit_logs_user_created` (user_id, created_at DESC) | 按用户+时间查询 |
| `ix_audit_logs_created_brin` (created_at BRIN) | 大范围时间扫描辅助 |

**查询优化器行为：** PostgreSQL 会根据查询条件选择性（selectivity）自动选择最优索引。如果时间范围很窄（几天），使用 `ix_audit_logs_created_at`；如果时间范围广但模块+类型选择性强，使用 `ix_audit_logs_module_action` + Bitmap Index Scan。

**预估性能：** 日志表预估随使用增长至 10 万级。典型查询（三个月 + 单模块）命中 <1000 条记录，耗时 <100ms。BRIN 索引在百万级记录后体现优势。

### 6.5 场景五：跨系统需求关联查询

**业务背景：** 用户在某个项目视图下查看需求时，需求详情页需要展示该需求关联的所有系统及其各自的子任务完成情况。

**SQL 示例：**
```sql
-- 查询需求关联的所有系统
SELECT p.id, p.name, p.status AS project_status
FROM requirement_project rp
JOIN projects p ON rp.project_id = p.id
WHERE rp.requirement_id = 42;

-- 按关联系统分组统计子任务完成情况
SELECT p.id AS project_id,
       p.name AS project_name,
       COUNT(t.id) AS total_tasks,
       COUNT(t.id) FILTER (WHERE t.status = 3) AS completed_tasks
FROM requirement_project rp
JOIN projects p ON rp.project_id = p.id
LEFT JOIN tasks t ON t.requirement_id = rp.requirement_id
                       AND t.project_id = rp.project_id
WHERE rp.requirement_id = 42
GROUP BY p.id, p.name;
```

**所需索引：**
| 索引 | 作用 |
|------|------|
| `ux_requirement_project` (requirement_id, project_id) | 唯一索引覆盖查询条件 |
| `ix_tasks_requirement` (requirement_id) | 按需求查子任务 |
| `ix_tasks_project` (project_id) | 按项目分组统计时筛选 |
| `ix_tasks_status` (status) | FILTER 子句利用索引加速 |

**预估性能：** 单条需求的关联项目数通常 1-5 个，子任务总数 <50 个。两个查询合计 <30ms。

### 6.6 索引设计原则总结

| 原则 | 说明 | 应用 |
|------|------|------|
| 选择性优先 | 高选择性列优先建索引 | status(7值) 比 priority(4值) 选择性更好，但两者都是中等选择性，适合列表筛选 |
| 覆盖索引 | 联合索引覆盖 WHERE + ORDER BY | `ix_audit_logs_user_created` = (user_id, created_at DESC) 同时覆盖筛选和排序 |
| 避免过度索引 | 每个索引都有写入成本 | 未对 `description`、`review_comment` 等 TEXT 字段建索引 |
| 部分索引 | 仅对经常查询的子集建索引 | `ix_documents_deleted_at` 仅包含 `deleted_at IS NOT NULL` 的行 |
| 外键必须索引 | 所有 FK 列建索引避免全表扫描 | 所有 `*_id` 列均有索引 |

## 7. 数据安全设计

### 7.1 行级数据隔离

行级数据隔离在**应用层（Laravel Eloquent Query Scope + Policy）**实现，数据库层作为可选的最后防线。

#### 7.1.1 数据可见性规则矩阵

| 用户类型 | 可见项目范围 | 可见需求范围 | 可见任务/缺陷范围 |
|---------|------------|------------|-----------------|
| 内部 IT 超管 | 全部 | 全部 | 全部 |
| 内部 IT PM/成员 | `project_members` 中分配的项目 | 关联到分配项目的需求 | 关联到分配项目的需求下的任务/缺陷 |
| 供应商用户 | `project.supplier_org` 为其所属组织（含子节点）的项目 | 关联到可见项目的需求 | 关联到可见项目的需求下的任务/缺陷 |
| 系统用户 | 无直接项目权限 | 仅自己提交的需求 (`submitter_id = self`) | 仅自己提交的缺陷 (`reporter_id = self`) |

#### 7.1.2 应用层实现方案（Laravel Query Scope + Trait）

**方案一：全局 Query Scope（推荐用于列表查询）**

```php
// app/Models/Traits/HasRowLevelFilter.php
namespace App\Models\Traits;

use App\Enums\UserType;
use Illuminate\Database\Eloquent\Builder;

trait HasRowLevelFilter
{
    /**
     * 应用行级数据过滤条件
     * 在每个需要行级隔离的 Model 的 boot() 中添加:
     *   static::addGlobalScope('rowLevel', function (Builder $builder) {
     *       $builder->applyRowLevelFilter(auth()->user());
     *   });
     */
    abstract public function scopeApplyRowLevelFilter(Builder $query, ?User $user): Builder;

    /**
     * 获取用户可见的 ID 集合（按业务模型覆写）
     */
    abstract protected function getAccessibleProjectIds(User $user): array;

// app/Models/Requirement.php
class Requirement extends Model
{
    use HasRowLevelFilter;

    protected static function booted(): void
    {
        static::addGlobalScope('rowLevel', function (Builder $builder) {
            if ($user = auth()->user()) {
                $builder->applyRowLevelFilter($user);
            }
        });
    }

    public function scopeApplyRowLevelFilter(Builder $query, ?User $user): Builder
    {
        if (! $user || $user->isSuperAdmin()) {
            return $query;
        }

        return match ($user->user_type) {
            UserType::INTERNAL => $query->whereHas('projects.members',
                fn ($q) => $q->where('user_id', $user->id)
            ),
            UserType::SUPPLIER => $query->whereHas('projects', function ($q) use ($user) {
                $q->whereIn('supplier_org_id', $user->getSupplierDescendantOrgIds());
            }),
            UserType::SYSTEM_USER => $query->where('submitter_id', $user->id),
            default => $query->whereRaw('1 = 0'),
        };
    }
}

// app/Models/User.php 中获取供应商子树节点 ID
class User extends Authenticatable
{
    /**
     * 获取当前供应商用户所属组织及其所有子孙节点的 ID 集合
     */
    public function getSupplierDescendantOrgIds(): array
    {
        return cache()->remember("user_{$this->id}_supplier_org_ids", 300, function () {
            $supplierOrg = $this->organizations()
                ->where('org_type', OrgType::SUPPLIER)
                ->first();

            if (! $supplierOrg) {
                return [];
            }

            return DB::table('organizations')
                ->withRecursiveExpression('org_tree', function ($q) use ($supplierOrg) {
                    $q->select('id')->from('organizations')
                        ->where('id', $supplierOrg->id)
                        ->unionAll(
                            DB::table('organizations as o')
                                ->join('org_tree as ot', 'o.parent_id', '=', 'ot.id')
                                ->select('o.id')
                        );
                })
                ->from('org_tree')
                ->pluck('id')
                ->toArray();
        });
    }
}
```

```php
class RequirementPolicy
{
    use HandlesAuthorization;

    public function view(User $user, Requirement $requirement): bool
    {
        if ($user->isSuperAdmin()) return true;

        return match ($user->user_type) {
            UserType::INTERNAL => $requirement->projects()
                ->whereHas('members', fn ($q) => $q->where('user_id', $user->id))
                ->exists(),
            UserType::SUPPLIER => $requirement->projects()
                ->whereIn('supplier_org_id', $user->getSupplierDescendantOrgIds())
                ->exists(),
            UserType::SYSTEM_USER => $requirement->submitter_id === $user->id,

        };

    {
        // 功能权限 + 行级权限组合校验
        if (! $user->hasPermission('requirement.edit')) return false;
        return $this->view($user, $requirement);
    }

    // create, delete, approve, assign...
}
```

### 7.3 审计字段设计

所有业务表统一使用以下审计字段模式：

```sql
-- 标准审计字段（每个业务表均包含）
created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),   -- 记录创建时间（Eloquent 自动维护）
updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),   -- 记录最后更新时间（Eloquent 自动维护）
created_by_id INTEGER    NOT NULL REFERENCES users(id),  -- 创建人
```

**部分表扩展审计字段：**
- `updated_by_id`: 记录最后编辑人（需求表、项目表）
- `deleted_at` + `deleted_by_id`: 软删除记录（文档表，30 天回收站）
- `reviewed_at`: 审核时间（需求表）
- `completed_at`: 完成时间（任务表）
- `closed_at`: 关闭时间（缺陷表）

**`updated_at` 触发器：** 所有带有 `updated_at` 字段的表均配置 `BEFORE UPDATE` 触发器自动更新该字段，避免应用层遗漏。Eloquent 的 `$timestamps` 属性会自动管理 `created_at` 和 `updated_at`，数据库触发器作为备选方案。

## 8. 数据生命周期

### 8.1 文档回收站 30 天自动清理策略

**机制：** Laravel SoftDeletes（`deleted_at` 字段） + 定时清理任务

```
文档删除操作：
  1. 用户点击"删除文档"
  2. 系统调用 $document->delete()（Eloquent SoftDeletes 自动设置 deleted_at = NOW()）
  3. deleted_by_id 由应用层记录
  4. 文档从前端列表中消失（Eloquent 默认过滤 deleted_at IS NOT NULL 的记录）
  5. 回收站中查询使用 Document::onlyTrashed()，恢复使用 $document->restore()

定时清理任务（Laravel Scheduler，每天凌晨 3:00 执行）：
  1. 查询 documents 表中 deleted_at <= (NOW() - INTERVAL '30 days') 的记录
  2. 物理删除文件系统上的文件（Laravel Storage facade）
  3. 物理删除数据库记录（->forceDelete()）
  4. 对 api_documents 表执行相同逻辑
  5. 对 folders 表执行相同逻辑
```

**SQL 清理语句：**
```sql
-- 删除 30 天前的回收站文档
DELETE FROM documents
WHERE deleted_at IS NOT NULL
  AND deleted_at <= (NOW() - INTERVAL '30 days');

-- 删除 30 天前的回收站接口文档
DELETE FROM api_documents
WHERE deleted_at IS NOT NULL
  AND deleted_at <= (NOW() - INTERVAL '30 days');

-- 删除 30 天前的回收站文件夹
DELETE FROM folders
WHERE deleted_at IS NOT NULL
  AND deleted_at <= (NOW() - INTERVAL '30 days');
```

**Laravel Artisan Command（配合 Scheduler）：**
```php
// app/Console/Commands/CleanupRecycleBin.php
namespace App\Console\Commands;

use App\Models\Document;
use App\Models\ApiDocument;
use App\Models\Folder;
use Illuminate\Console\Command;
use Illuminate\Support\Facades\Storage;

class CleanupRecycleBin extends Command
{
    protected $signature = 'recycle:cleanup {--days=30 : 回收站保留天数}';
    protected $description = '清理过期的回收站文档';

    public function handle(): int
    {
        $cutoff = now()->subDays($this->option('days'));

        // 物理删除文件，然后删除数据库记录
        $documents = Document::onlyTrashed()
            ->where('deleted_at', '<=', $cutoff)
            ->get();

        foreach ($documents as $doc) {
            if ($doc->file) {
                Storage::delete($doc->file);
            }
            $doc->forceDelete();
        }

        $apiDocCount = ApiDocument::onlyTrashed()
            ->where('deleted_at', '<=', $cutoff)
            ->forceDelete();

        $folderCount = Folder::onlyTrashed()
            ->where('deleted_at', '<=', $cutoff)
            ->forceDelete();

        $this->info("清理了 {$documents->count()} 个文档, {$apiDocCount} 个接口文档, {$folderCount} 个文件夹");

        return self::SUCCESS;
    }
}

// routes/console.php (Laravel Scheduler)
Schedule::command('recycle:cleanup --days=30')
    ->dailyAt('03:00')
    ->withoutOverlapping();
```

### 8.3 项目归档后的数据状态

| 数据维度 | 归档后行为 | 说明 |
|---------|-----------|------|
| 项目状态 | `status = 3 (ARCHIVED)` | 不可逆变更 |
| 新增需求 | 禁止 | 前端隐藏"新建需求"按钮 + 后端校验 |
| 现有需求 | 只读 | 可查看历史数据，不可编辑、变更状态 |
| 新增任务 | 禁止 | 通过需求状态联动禁止 |
| 现有任务 | 只读 | 可查看，不可编辑状态 |
| 新增缺陷 | 由业务规则决定 | 建议允许（已上线系统的缺陷仍需追踪） |
| 文档 | 只读 | 可下载，不可上传/编辑 |
| 操作日志 | 保留 | 归档不删除操作日志 |
| 通知 | 停止 | 归档项目下的任务不再发送到期提醒 |

**实现方式：** 在业务逻辑层（Service 层）校验 `project.status == ARCHIVED`，拒绝写操作请求。只读操作（GET 请求）不受影响。

## 10. 关键设计决策说明

### 10.1 跨系统需求关联（N:M）

**设计选择：** 使用独立的关联表 `requirement_project` 实现 N:M 关系，而非在需求表中使用 ArrayField。

**理由：**
- 外键约束保证数据完整性（关联的项目必须存在）
- 索引可优化 JOIN 查询（按项目查需求 or 按需求查项目）
- Laravel Eloquent 的 `belongsToMany` 关系天然支持，无需额外序列化逻辑
- 删除项目时可通过外键约束自动校验（`ON DELETE RESTRICT` 满足 BR-1-03）

### 10.2 需求版本变更记录

**设计选择：** 使用独立的 `requirement_versions` 表，`changes` 字段使用 JSONB 存储变更 diff。

**理由：**
- JSONB 灵活存储变更字段列表（不同变更可能有不同字段组合）
- 独立表避免主表膨胀（需求表保持精简，历史记录按需查询）
- 支持索引（`ix_requirement_versions_req_ver` 按需求+版本号高效排序）
- JSONB 支持未来扩展（如增加变更原因、关联的评审意见等）

### 10.3 三种独立组织架构树

**设计选择：** 使用单表 `organizations` + `org_type` 字段区分三类树，通过 `parent_id` 实现简单层级结构，查询使用递归 CTE。

**理由：**
- 避免三张结构相同的表，减少代码重复
- `org_type` 天然隔离三类树的节点，按 `org_type` 查询可直接获取某类用户的组织树
- 三类树的节点操作逻辑（增删改查）完全相同，统一模型更简洁
- `parent_id + WITH RECURSIVE` 模式在小规模数据（<500 节点）下性能优秀，且实现简单
- 相比 MPTT 方案，不需要维护 `lft`/`rght`/`tree_id` 等额外字段，节点增删移动无需重新计算左右值

### 10.4 行级数据隔离 -- 项目-供应商关联

**设计选择：** `projects.supplier_org_id` 关联供应商的组织节点，通过递归 CTE 获取供应商公司下所有子节点人员。

**隔离逻辑链：**
```
用户 → organization_user.organization → 递归 CTE 子树查询 → 找到供应商公司下所有子节点
     → projects.supplier_org (IN 子节点列表) → 获得可见项目
     → requirement_project (M:N) → 获得可见需求
     → tasks / defects (FK 到 requirement) → 获得可见任务/缺陷
```

**数据隔离示例：**
```
供应商 A 公司的组织树：
  [供应商A公司] (id=3, parent_id=NULL, org_type=2)
    ├── [开发一部] (id=4, parent_id=3)
    │   ├── 张三 (id=5, parent_id=4)
    └── [测试部]   (id=6, parent_id=3)
        └── 李四 (id=7, parent_id=6)

用户"张三"属于 org_id=5 (开发一部分组)。
通过递归 CTE 从 id=5 向上获取祖先：[张三, 开发一部, 供应商A公司]。
再通过递归 CTE 从供应商A公司 (id=3) 向下获取所有子节点：[供应商A公司, 开发一部, 张三, 测试部, 李四]。
查询 projects WHERE supplier_org_id IN (3, 4, 5, 6, 7)。
张三可见 supplier_org 为该供应商下任意节点的所有项目。
```

### 10.5 权限模型设计

**设计选择：** RBAC（基于角色的访问控制）+ 行级数据过滤。

**三层权限体系：**

| 层级 | 控制内容 | 实现 |
|:----:|---------|------|
| 功能权限 | 用户能否执行某操作（如创建需求） | roles -> permissions (N:M)，Laravel Policy / Gate 校验 |
| 数据权限 | 用户能访问哪些数据行 | Eloquent Global Query Scope 注入过滤条件，按 user_type + 项目归属过滤 |
| 内容权限 | 同一页面内不同角色看到不同按钮 | 前端根据用户权限列表动态渲染，后端 API 做最终校验 |

### 10.6 Laravel SoftDeletes 使用策略

**设计选择：** 使用 Laravel 内置的 `Illuminate\Database\Eloquent\SoftDeletes` trait，通过 `deleted_at` 时间戳字段标记逻辑删除。替代原先 Django 的 `is_deleted` 布尔 + `deleted_at` 双字段模式。

**适用表：**
| 表名 | 使用 SoftDeletes | 理由 |
|------|:---:|------|
| `documents` | 是 | 文档回收站，30 天可恢复 |
| `api_documents` | 是 | 接口文档回收站 |
| `folders` | 是 | 文件夹回收站 |
| `requirement_attachments` | 是 | 附件删除后进入回收站 |

**Eloquent 关键方法：**
```php
// 普通查询（自动排除已删除记录）
$docs = Document::all();

// 包含已删除记录
$docs = Document::withTrashed()->get();

// 仅查询已删除记录
$docs = Document::onlyTrashed()->get();

// 恢复
$document->restore();

// 永久删除
$document->forceDelete();
```
