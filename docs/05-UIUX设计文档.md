## 1. 设计目标与原则

### 1.1 设计理念

IPMS 是一个面向企业内部、承载三方协作的需求开发管理平台。设计围绕三个核心理念展开：

- **专业高效**：信息密度适中，操作路径短，减少不必要的点击和页面跳转。每个页面的核心操作不超过 3 步可达。
- **清晰透明**：状态流转可视化，变更历史可追溯，操作反馈即时。用户在任何时候都应该清楚"当前在哪、能做什么、发生了什么"。
- **权限感知**：界面随角色自适应。不同用户登录后看到不同的菜单、不同的操作按钮、不同的数据范围，流畅而无割裂感。

### 1.2 核心交互原则

| 原则 | 说明 | 设计体现 |
|------|------|---------|
| **渐进呈现** | 先展示概览，按需展开细节 | 项目列表 → 项目详情 → 需求详情逐层深入；子任务、变更记录默认折叠 |
| **上下文操作** | 操作按钮紧邻目标对象 | 需求详情页的状态流转操作区常驻页面顶部；列表行内操作（编辑、删除） |
| **防错设计** | 在错误发生前阻断 | 删除二次确认、已验收需求禁用编辑、已关联需求的项目禁止删除并给出明确提示 |
| **反馈闭环** | 每次操作都有明确反馈 | Toast 提示成功/失败、状态流转后操作区即时刷新、进度条实时更新 |
| **一致性** | 同类元素相同行为 | 所有列表页共用一套筛选-搜索-分页模式；所有详情页共用一套布局骨架 |
| **容错与恢复** | 允许犯错并提供补救路径 | 驳回的需求可修改重提、已关闭缺陷可重新打开、文档删除进入回收站 |

## 2. 信息架构

### 2.1 全局导航结构

采用**侧边栏 + 顶部栏**的经典企业后台布局：

```
┌──────────────────────────────────────────────────────────────┐
│  [Logo] IPMS                    [通知铃铛] [用户头像 ▼]      │  ← 顶部导航栏 (高度 56px)
├────────────┬─────────────────────────────────────────────────┤
│            │                                                  │
│  导航菜单   │              内容区域                            │
│            │                                                  │
│  · 项目    │  ┌──────────────────────────────────────────┐   │
│  · 需求    │  │  面包屑: 首页 > 项目 > SAP B1             │   │
│  · 任务    │  │  ─────────────────────────────────────    │   │
│  · 缺陷    │  │                                          │   │
│  · 文档    │  │         页面主体内容                      │   │
│  · 日志    │  │                                          │   │
│  · 组织    │  │                                          │   │
│  · 设置    │  │                                          │   │
│            │  └──────────────────────────────────────────┘   │
│  (可折叠)  │                                                  │
│            │                                                  │
├────────────┴─────────────────────────────────────────────────┤
│  Copyright © 2026 IPMS. All rights reserved.                  │  ← 底部状态栏 (高度 32px)
└──────────────────────────────────────────────────────────────┘
```

**设计决策**：
- 选择侧边栏而非顶部导航，因为功能模块较多（8 个），顶部 Tab 空间不足且不易扩展。
- 侧边栏宽度默认为 **220px**，可折叠为 **64px**（仅显示图标），释放内容区域空间。
- 顶部栏固定，侧边栏固定，内容区域独立滚动。

### 2.2 菜单层级设计

```
IPMS
├── 🏠 首页（登录后默认落地页，展示个人工作台概览）
│
├── 📁 项目管理
│   └── 项目列表（所有有权限项目的卡片/列表视图）
│       └── 项目详情（点击进入，含项目概览、需求统计）
│
├── 📋 需求管理
│   ├── 全部需求（按状态筛选的列表视图）
│   └── 我的需求（当前用户相关的需求，系统用户的主视图）
│
├── ✅ 任务管理
│   ├── 我的任务（当前用户待办/进行中的任务）
│   └── 项目任务（按项目筛选所有任务）
│
├── 🐛 缺陷管理
│   └── 缺陷列表（按状态/严重程度筛选）
│
├── 📄 文档管理
│   └── （从项目维度进入，侧边栏点击后引导选择项目）
│
├── 📊 操作日志（仅内部 IT 可见）
│
├── 🏛️ 组织架构（仅内部 IT 超级管理员可见）
│
└── ⚙️ 系统设置（仅内部 IT 超级管理员可见）
    ├── 基本配置
    └── 通知配置
```

#### 内部 IT 超级管理员（全局可见）

```
🏠 首页
📁 项目管理
📋 需求管理
   ├── 全部需求
   └── 我的需求

   ├── 我的任务
   └── 项目任务
🐛 缺陷管理
📄 文档管理
📊 操作日志
🏛️ 组织架构
⚙️ 系统设置
```

#### 内部 IT 项目经理（分配范围内）

```
🏠 首页
📁 项目管理（仅可见被分配的项目）
📋 需求管理
   ├── 全部需求（分配范围内的需求）
   └── 我的需求
✅ 任务管理
   ├── 我的任务
   └── 项目任务

```

> 与超管的差异：无"组织架构"和"系统设置"菜单；"项目管理"中无新建/删除按钮。

#### 内部 IT 项目成员（分配范围内）

```
🏠 首页
📁 项目管理（仅可见被分配的项目，只读）
📋 需求管理
   ├── 全部需求（分配范围内）
   └── 我的需求
✅ 任务管理
   ├── 我的任务
   └── 项目任务
🐛 缺陷管理
📄 文档管理
```

> 与项目经理的差异：无"操作日志"菜单；需求详情页无"审核"按钮。

#### 供应商项目经理（被分配项目）

```
🏠 首页
📁 项目管理（仅可见被分配的项目，只读）
📋 需求管理（仅被分配的需求）
✅ 任务管理
   ├── 我的任务
   └── 项目任务（本团队负责的任务）
🐛 缺陷管理（本团队相关的缺陷）
📄 文档管理（被分配项目的文档）
```

> 与内部 IT 的差异：无"操作日志"菜单；需求详情页操作按钮不同（"开始开发"而非"审核"）。

#### 供应商开发人员/测试人员（被分配项目）

```
🏠 首页
✅ 任务管理
   ├── 我的任务
   └── 项目任务
🐛 缺陷管理（被分配的缺陷）
📄 文档管理（只读）
```

> 菜单最精简，聚焦于任务执行和缺陷处理。

#### 系统用户（仅自己的需求）

```
🏠 首页
📋 我的需求（仅自己提交的需求）
🐛 缺陷管理（仅自己提交的缺陷）
```

> 最精简的菜单。系统用户与内部 IT 和供应商看到的系统完全不同。

- **供应商项目经理**：仅看到被分配的项目卡片，无"新建项目"按钮，无"编辑"/"删除"操作。
- **系统用户**：无此页面访问权限。

### 5.4 权限不足的提示方式

根据不同场景采用不同的提示策略：

| 场景 | 提示方式 |
|------|---------|
| **菜单项不可见** | 无权限的菜单项直接不渲染，用户看不到该入口 |

| **操作按钮不可用** | 按钮置灰（disabled 状态），hover 时 Tooltip 显示"您没有权限执行此操作" |

| **功能引导** | 首次登录时，根据角色展示不同的欢迎引导弹窗，介绍可用的功能模块 |

### 7.2 弹窗 / 抽屉使用场景

> **注意**：以下组件名称以 Element Plus 为准。关键名称差异：Ant Design 的 `Modal` 对应 Element Plus 的 `el-dialog`；`Popconfirm` 对应 `el-popconfirm`。

| 组件 | 使用场景 | 尺寸 |
|------|---------|------|
| **模态弹窗 (el-dialog)** | 表单填写（新建/编辑需求、任务、缺陷）、确认操作、查看详情 | 宽度 520px / 640px / 800px（视内容量），最大高度 80vh |
| **侧边抽屉 (el-drawer)** | 需求详情、任务详情、缺陷详情（替代页面跳转的场景）、筛选面板 | 宽度 480px / 640px / 800px |
| **下拉面板 (el-popover)** | 通知列表、用户菜单、列筛选、快速操作 | 宽度 280px - 360px |
| **气泡确认 (el-popconfirm)** | 删除确认等简单二次确认 | 宽度 300px |
| **Tooltip (el-tooltip)** | 图标说明、截断文字完整展示、禁用按钮原因 | 最大宽度 300px |

**弹窗使用原则**：
- 简单表单和确认操作使用模态弹窗，保持在当前上下文中操作。
- 内容较多的详情页（如需求详情）优先使用页面跳转，次选抽屉。
- 弹窗打开时，背景添加半透明黑色遮罩（rgba(0,0,0,0.45)），点击遮罩不关闭弹窗（防止误操作丢失填写内容），必须通过"取消"或"关闭"按钮关闭。
- 弹窗打开时，按 ESC 键等同于点击"取消"。
- 弹窗内如果表单较长，弹窗内部可滚动，底部操作按钮区域固定。

- 删除项目、需求、任务、缺陷、文档
- 驳回需求（附驳回原因必填）
- 挂起任务（附挂起原因必填）
- 需求验收确认
- 缺陷拒绝关闭
- 用户账号禁用
- 项目归档

### 7.5 数据加载与分页

#### 加载策略

| 场景 | 加载方式 |
|------|---------|
| 页面初始加载 | 骨架屏 + 顶部进度条 |
| 列表翻页/筛选 | 列表区域短暂 loading 遮罩（半透明 + 转圈图标） |
| 表单提交 | 按钮内 loading 图标 + 文字变为"提交中..."，按钮禁用防重复点击 |
| 文件上传 | 进度条显示上传百分比 |
| 下拉加载更多 | MVP 不使用无限滚动，统一使用分页器 |

#### 分页器（el-pagination）

```
共 256 条    [<]  1  2  3  4  5  ...  13  [>]    每页 [20 ▾] 条
```

- 使用 Element Plus `el-pagination` 组件，默认每页 20 条，可选 10 / 20 / 50。
- 分页器位于列表底部居中。
- 当总页数 <= 1 时，不显示分页器。
- 页码按钮宽度 32px，当前页背景 Primary-500 白色文字，其他页灰色文字。

### 7.6 响应式策略

**PC 优先设计，以 1280px 为最佳浏览宽度。**

| 断点 | 宽度范围 | 适配策略 |
|------|---------|---------|
| 大屏 | >= 1440px | 内容区域最大宽度 1280px，居中显示，两侧留白 |
| 标准屏 | 1024px - 1439px | 内容区域 100% 宽度，侧边栏默认折叠为 64px |
| 小屏 | < 1024px | 侧边栏自动折叠 + 遮罩层，内容区域 100% 宽度；卡片视图从 3 列变为 2 列 |

**关键适配规则**：
- 最小支持宽度：1024px（低于此宽度显示提示"请使用更大屏幕访问"）。
- 侧边栏在小屏下默认折叠，hover 时展开为浮动层（不挤压内容区域）。
- 表格在小屏下，固定第一列（标题），其他列横向滚动。
- 弹窗在小屏下宽度自适应，最小 360px，最大 90vw。

## 9. 可用性检查清单

### 9.1 导航与定位

| 编号 | 检查项 | 设计决策 |
|:----:|--------|---------|
| N-01 | 用户是否始终知道自己在哪？ | 面包屑导航 + 侧边栏当前菜单高亮 + 页面标题 |
| N-02 | 用户是否能轻松返回上一级？ | 面包屑可点击返回任意层级 + 浏览器后退按钮可用 |
| N-03 | 重要功能是否在 3 次点击内可达？ | 首页快捷入口（待审核需求数可点击直达）+ 侧边栏一键导航 |

### 9.2 可视反馈

| 编号 | 检查项 | 设计决策 |
|:----:|--------|---------|
| V-01 | 所有可点击元素是否有 hover 态？ | 按钮颜色变深 + 指针变手型；链接变下划线；表格行变浅蓝背景 |
| V-02 | 操作是否给出即时反馈？ | 所有操作触发 Toast 提示；按钮 loading 态防重复点击 |
| V-03 | 当前选中状态是否明显？ | 侧边栏菜单：蓝色指示条 + 浅蓝背景；Tab：蓝色下划线 + 文字变色 |
| V-04 | 系统状态是否可见？ | 全局加载进度条；表单提交中按钮状态变化；操作结果 Toast |

### 9.3 表单

| 编号 | 检查项 | 设计决策 |
|:----:|--------|---------|
| F-01 | 必填字段是否有标识？ | 标签后红色星号 (*) |
| F-02 | 是否有实时校验反馈？ | 字段失焦触发校验，红色边框 + 下方提示文字 |
